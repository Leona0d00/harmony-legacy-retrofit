# 硬件联调与演示手册（MAX3485 闭环）

> 当前演示链路：PC Modbus 从站 ⇄ USB-RS485 ⇄ MAX3485 ⇄ Hi3861/OpenHarmony ⇄ 2.4GHz Wi-Fi/MQTT ⇄ PC 运维看板。
> PC 模拟寄存器作为测试数据源；RS485 实体收发、板端解析、无线传输、告警和看板均为实际运行链路。真实工业设备接入仍待现场适配。

## 0. 一次性准备

1. **PC 环境**：项目专属 Python 3.9 venv，位于 `src\project\.venv`。

   ```powershell
   cd D:\hi3861_hdu_iot_application\src\project
   .\.venv\Scripts\Activate.ps1  # powershell
   #.\.venv\Scripts\activate.bat # cmd
   python -m pip install -r tools\requirements.txt
   ```

2. **Mosquitto**：监听 `0.0.0.0:1883`，防火墙允许当前专用网络访问 1883。Broker 地址需与 `firmware\include\app_config.h` 及 `tools\config.yaml` 一致。
3. **网络**：PC 与板卡接入同一热点/局域网。Hi3861 仅支持 **2.4GHz**；使用 `iroha` 热点时，PC Broker 当前地址为 `192.168.43.184`。切换网络后复核 PC IP 并同步两处 Broker 配置、重编译固件。
4. **串口**：当前设备管理器识别 USB-RS485 为 **COM11（CH343）**，`tools\config.yaml` 已配置 COM11。板载 CH340（COM8）用于烧录/日志；COM3 是蓝牙串口，不要误用。
5. **烧录**：使用 `D:\DevTools_Hi3861V100_v1.0\burntool\BurnTool.exe`，烧录速率 921600。烧录结束后 Disconnect、打开 COM8 115200 8N1，再按一次 **RST** 启动新固件。正常运行中不需要周期性按 RST。

## 1. 硬件接线

板端使用手动方向 MAX3485 3.3V 模块。以下 TXD/RXD 按模块官方丝印定义：TXD 是模块发送输出，RXD 是模块接收输入，故与主控 UART 信号交叉连接。

| 模块接口 | 接到 | 说明 |
| --- | --- | --- |
| TXD | P1 第 28 脚（IO1 / UART1_RXD） | 模块发送输出 → 主控接收 |
| RXD | P1 第 30 脚（IO0 / UART1_TXD） | 主控发送 → 模块接收输入 |
| EN | P1 第 29 脚（IO8） | 高电平发送、低电平接收，已实测 |
| 左侧 3V3 | P1 第 10/12/14/16 脚任一 | MAX3485 供电，不接 5V |
| 左侧 GND | P1 第 13/15/17 脚任一 | 主控侧地 |
| A / B | USB-RS485 适配器 A / B | 先按同名端连接；无应答时检查总线极性 |
| 右侧 GND | USB-RS485 适配器 GND | 按模块官方接法作为总线参考地 |

模块左、右两侧 GND 按官方说明分别接主控地与总线适配器地，不额外跨接短路。P1 第 16 脚 3.3V 已由实物核验；原理图 PDF 对此脚的标注不一致，接线按实板核验。接线和改线均先断电；不要把 USB-RS485 的 A/B 接到 IO0/IO1。

## 2. 板端启动确认

烧录后按 RST，从 COM8（115200 8N1）观察：

- 出现 `[project] device=普中演示从站 v1 protocol=modbus-rtu points=3`；
- 出现 `wifi connected, ip=...`，热点必须为 2.4GHz；
- MQTT 初始化成功并发送 boot/周期心跳；
- 板端 UART1 使用 IO0/IO1，IO8 控制 MAX3485 EN；发送后以帧长和波特率计算延时，再切回接收。

PC 可用 `python tools\mqtt\monitor.py` 短时查看原始消息；该工具持续订阅，自动验收时更推荐直接使用下文的限时脚本。

## 3. 常驻在线人工演示（主演示流程）

准备两个终端，都从项目目录激活 venv。检查板子已上电并连接热点、Broker 正常，且 USB-RS485 适配器为 COM11。

**终端一：启动交互式 Modbus 从站**

```powershell
python tools\modbus_sim\slave_rtu.py --interactive
```

**终端二：启动常驻运维看板**

```powershell
python tools\ops\ops_console.py
```

等待看板显示设备“● 在线”及温度、湿度、状态点位后，在终端一输入：

| 输入命令 | 看点 |
| --- | --- |
| `show` | 查看当前模拟寄存器原始值与工程量 |
| `temp 35.6` | 温度寄存器改为 raw=356，看板下一轮读取后显示 35.6℃ |
| `humidity 65.0` | 湿度改为 raw=650，看板显示 65.0%RH |
| `status 0` | 修改状态寄存器 |
| `alarm` | 温度改为 raw=850（85.0℃），板端阈值判断后在告警主题上报 |
| `normal` | 恢复启动时配置的初值，观察温度恢复及告警解除 |
| `set 0x0000 420` | 直接按保持寄存器地址设置原始值 |
| `help` / `quit` | 查看完整命令 / 正常退出并释放 COM11 |

交互提示的“寄存器已更新”表示从站内存值已修改；看板收到的新报文才代表板端采集闭环完成。固件配置 `poll_ms=1000`，Hi3861 LiteOS-M tick 为 100Hz，实测完整点位轮询约 **10 秒一轮**，请给看板刷新留出一轮时间。命令行等待输入时从站仍在后台线程正常应答。

**串口占用规则：**交互式从站运行期间，不能另启动 `slave_rtu.py` 常驻实例或自动验收脚本，否则会争用 COM11。看板可与交互从站同时运行。演示结束在交互终端输入 `quit` 或按 Ctrl+C，确认程序退出后 COM11 自动释放。

## 4. 限时自动验收（补充演示 / 留档）

先停止交互式从站并释放 COM11，再运行：

```powershell
python tools\verify\verify_rs485.py
```

脚本在受管线程内启动同一实现的 Modbus 从站，自动验证正常三点位、温度告警（850）和告警恢复；每阶段默认最多等待 25 秒，结束后关闭 MQTT 订阅和串口服务。可加 `--timeout 40` 延长每阶段等待。

可同时运行 `ops_console.py` 观看自动验收数据。自动验收不改写 `tools\config.yaml`，温度告警值仅在运行内存里生效。验收脚本自身会启动从站，因此期间不要另开任何 Modbus 从站。

## 5. 无硬件备用演示

只有在无板或无 RS485 适配器时才使用 `sim_device.py`：

```powershell
python tools\sim\sim_device.py --duration 60 --alarm
```

该脚本直接向 MQTT 发布模拟板卡消息，**不经过 Modbus RTU、实体 RS485 或 Hi3861 采集**；展示时应明确标注为软件模拟链路，不替代本手册的完整硬件演示。

## 6. 故障排查

- **COM11 打不开：**关闭交互从站、限时验收及串口调试工具，只保留一个 USB-RS485 程序占用 COM11。
- **板端 Wi-Fi 扫不到热点：**确认热点在 2.4GHz；5GHz（如信道 149）Hi3861 无法连接。
- **Modbus 无应答：**检查 TXD→IO1、RXD→IO0、EN→IO8、EN 高发送/低接收、模块 3.3V、左右 GND 对应关系及 A/B 标注。
- **板端 MQTT 失败：**确认 PC 与板子同网、Broker 正在监听 1883、`app_config.h` 的 Broker IP 与 PC 当前 IP 一致。
- **刷新比预期慢：**当前轮询约 10 秒一轮；应等下一轮读完，不要按每秒刷新判断故障。
